# Deterministic PCM audio contract

Foundation uses one Rust WAV decoder and one fixed-point PCM mix contract for native SDL and the browser AudioWorklet.

## Canonical sample stream

- 44,100 frames per second, signed 16-bit, interleaved stereo PCM.
- WAV conversion is shared Rust code: PCM 8/16/24/32-bit and IEEE float32, plus WAVE_FORMAT_EXTENSIBLE PCM/float tags with matching valid/container widths.
- Browser-only formats supported by `decodeAudioData()` (such as OGG, MP3 and AAC where the browser supports them) are retained: decoded Float32 channels are quantized and resampled by shared Rust code into the same canonical PCM before Worklet registration. Native `load_wav` uses the shared RIFF/WAVE parser; compressed browser-only formats have no native equivalent in this host.
- Mono is duplicated to stereo. For files with more than two channels, the first two channels are used.
- Sample-rate conversion uses rational source positions and integer linear interpolation.
- Volume is clamped to 0..400 percent and applied with integer multiplication/division, truncating toward zero.
- The diagnostic beep is generated by shared Rust code, producing the same PCM on both targets.

## Integer mixer

The mixer has 48 voice slots. It iterates slots in order, sums each channel in signed 32-bit integers, and clamps once to the S16 range. Replaying a clip cuts its previous voice and restarts at frame zero. When the pool is full, the oldest sequence is stolen with the same wrapping signed-32-bit sequence comparison used by Rust. Looping wraps without an inserted silent frame.

The AudioWorklet mirrors that allocator and per-frame algorithm. It performs Float32 conversion only after integer summation and saturation. It also resamples the already-mixed 44.1 kHz stream to the AudioContext device rate when the browser cannot provide 44.1 kHz. Thus the integer mix result is bit-for-bit equivalent at the canonical PCM boundary; browser scheduling, output-rate resampling, the operating system and the physical device are outside that guarantee.

## Browser fallback and deployment

AudioWorklet is loaded after `resume_audio()` is called from a user gesture. Foundation builds the processor into an in-memory Blob URL. A restrictive Content Security Policy must allow the relevant `blob:` worker/module source. When AudioWorklet is unavailable or blocked, the host falls back to AudioBufferSourceNode playback using the same canonical decoded PCM. That fallback does not claim identical multi-voice mixer semantics.

The JavaScript processor contract is tested by `tests/audio_worklet.test.mjs`. Rust decoder and mixer tests live beside `AudioMixer` in `src/audio.rs.
